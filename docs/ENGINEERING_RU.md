# Инженерный обзор KitobYor

## Почему модульный монолит

Задача проекта — упростить работу школьной библиотеки. Django Templates и небольшой JavaScript обеспечивают интерфейс без отдельной frontend-сборки. REST API использует тот же слой сервисов. PostgreSQL предназначен для реальной многопользовательской работы, SQLite — для воспроизводимого локального демо.

## Предметная модель

School и Membership задают границу доступа. Student и Enrollment разделяют ученика и его класс в конкретном учебном году. Book описывает учебник, Edition — год выпуска, Stock — остаток, Tariff — цену аренды на учебный год. Loan и LoanLine фиксируют выдачу и снимок цены. Invoice и Payment отражают начисление и подтверждённую оплату.

Изменение текущего тарифа не меняет историческую стоимость уже выданных книг. Технические коды остаются внутренними идентификаторами; сотрудник не обязан вводить их вручную.

## Выдача и конкурентные операции

Сервис проверяет пользователя, школу, класс, доступность и ожидаемую сумму. Операции с остатком, выдачей, счётом и аудитом выполняются атомарно. Блокировка обеспечивает последовательность конфликтующих операций в PostgreSQL. Idempotency token связывает повторный запрос с исходной операцией.

Для редактирования каталога используется revision. Если другой сотрудник уже изменил остаток или тариф, старая форма получает конфликт, а не перезаписывает изменения. Тесты блокировок требуют PostgreSQL: успешный прогон SQLite не подтверждает такое поведение.

## Отправка SMS

Финансовая операция создаёт запись уведомления; сетевой/serial I/O вынесен в worker. Драйвер кодирует кириллицу в UCS2 PDU и разбивает длинные сообщения на части. Состояния частей сохраняются отдельно, чтобы после сбоя не повторять уже принятые части.

До передачи содержимого безопасная ошибка допускает ограниченный retry. После границы передачи неоднозначный ответ переводит сообщение в uncertain. Решение о повторе принимает оператор после проверки. Эксклюзивный lock не допускает одновременно два worker-а для одного модема. Гарантия end-to-end exactly-once не заявляется.

## Эксплуатация

Compose разделяет базу, миграции, веб, HTTPS proxy и необязательный SMS worker. Приложение запускается без root; роль PostgreSQL не superuser. Секреты задаются окружением и не включаются в Git. Резервная копия полезна только вместе с проверенным восстановлением.

SMS-модем и SIM — внешние зависимости. Docker и реальное оборудование должны пройти отдельную приёмку. Номер счёта не является банковской интеграцией.

## Что смотреть при ревью

1. `library/services.py` — транзакции, остатки, снимки цены и повторные запросы.
2. `library/permissions.py` и scoped queries — границы школы и роли.
3. `library/sms/` — граница передачи и восстановление состояния.
4. `library/tests_hardening.py`, `library/tests_sms.py` — негативные сценарии и сбои.
5. `compose.yaml` и `deploy/` — эксплуатационные настройки.

Документ описывает реализацию, а не измеренное ускорение работы или подтверждённый масштаб внедрения. Такие показатели потребуют пилотного использования.
